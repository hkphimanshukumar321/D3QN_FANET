# Simulation Metrics: Formulas and CSV Schema

This document details the exact mathematical formulas, assumptions, and data schemas for every CSV file generated by the FANET MAC simulator.

---

## 1. Core Mathematical Formulas

These formulas reflect the exact logic implemented in `algorithms/baseline/baseline.py` and `work/run_experiments.py`.

### 1.1 Throughput
- **Description:** The effective payload data rate successfully delivered across the wireless channel, excluding all MAC/PHY overhead headers, ACKs, or collided frames.
- **Formula:** 
  `Throughput (bps) = (Total Successful Packets * Payload Size in Bits) / Simulation Time in Seconds`
  `Throughput (Mbps) = Throughput (bps) / 1,000,000`
- **Units:** Megabits per second (Mbps)
- **Measured:** Averaged over the entire simulation run per given traffic load.
- **Assumptions:** Fixed packet size (`PAYLOAD_BYTES`), ideal channel (no fading).

### 1.2 End-to-End Delay
- **Description:** The total physical time a packet spends in the system from the exact microsecond it is generated in the application layer to the microsecond it finishes successful transmission over the air.
- **Formula:** 
  `Per-Packet Delay = (Slot_Transmission_Success * SLOT_TIME_S) - Time_Packet_Generated`
  `Average E2E Delay = Sum of all Per-Packet Delays / Total Successful Packets`
- **Units:** Seconds (s)
- **Measured:** Per successful packet natively (FIFO), then averaged over the run. Packets dropped due to queue overflow or MAC retry exhaustion are excluded from this average.

### 1.3 Channel Utilization Ratio
- **Description:** The fraction of total simulation time where the channel was actively carrying successful data or legitimate control frames (depending on protocol). 
- **Formula:** 
  `Utilization = Total Channel Busy Slots / Total Simulation Slots`
- **Units:** Decimal ratio (0.0 to 1.0)
- **Protocol Differences:**
  - **CSMA/CA:** "Busy Slots" includes Data Tx, SIFS, ACKs, RTS/CTS, and collisions.
  - **TDMA:** "Busy Slots" tracks the exact data transmission time out of the total TDMA frame guard allocations.
  - **ALOHA:** Tracks raw collision and transmission slot overlap.

### 1.4 Packet Drops
- **Description:** The total number of packets permanently lost.
- **Formula:** 
  `Total Drops = Drops_Queue_Full + Drops_MAC_Retries_Exhausted`
- **Units:** Integer (Packets)
- **Assumptions:** Queue drops occur instantly if arrival happens when queue capacity (`QMAX`) is saturated. MAC drops occur in CSMA/CA if a single packet collides `MAX_RETRY` consecutive times.

### 1.5 Average Queue Length
- **Description:** The average number of packets residing in the buffer of any given node at any time.
- **Formula:** 
  `Average Queue Length = Sum(Current System Queue Size at every slot) / (Total Slots * N)`
- **Units:** Fractional Packets

## 2. CSV Output Data Schemas

The simulator outputs four primary CSV files per trial run inside `results/{CONFIG}/trial_{ID}/csv/`.

### 2.1 `summary_metrics.csv`
Contains the overarching macro-metrics comparing all protocols across the simulated traffic loads.
- `Offered_Load_pps`: (Integer) Total network aggregate traffic generation rate (Packets/sec). $\lambda_{node} = \text{Offered\_Load\_pps} / N$.
- `{PROTOCOL}_Throughput_Mbps`: (Float) Average throughput computed via the formula above.
- `{PROTOCOL}_Drops`: (Integer) Total combined queue and MAC dropped packets.
- `{PROTOCOL}_Q_len`: (Float) Average queue occupancy observed across all nodes.
- `{PROTOCOL}_Delay_s`: (Float) Average End-to-End delay in precision seconds.
- `{PROTOCOL}_Util`: (Float) Fractional channel utilization.
- `{PROTOCOL}_Collisions`: (Integer) Absolute count of collision events observed on the channel.

### 2.2 `buffer_usage_{PROTOCOL}.csv`
A high-resolution, time-series log taking periodic snapshots of the physical queue memory states. Tracked by `LOG_INTERVAL_SLOTS`.
- `slot_index`: (Integer) The absolute discrete simulation time unit of the snapshot.
- `q_max`: (Integer) The total theoretical queue slot capacity of the network (`N * QMAX`).
- `q_allotted`: (Integer) Memory physically mapped/allocated to the queues (currently matches `q_max`).
- `q_used`: (Integer) The exact number of packets currently residing in all buffers at `slot_index`.
- `q_wasted`: (Integer) Unused buffer memory (`q_allotted - q_used`).
- `enqueues`: (Integer) Total packets safely entering the queue since the last snapshot.
- `dequeues`: (Integer) Total packets successfully clearing the queue and transmitting since the last snapshot.
- `drops`: (Integer) Total packets hard-dropped due to overflow or MAC failure since the last snapshot.

### 2.3 `ack_success_log.csv`
Detailed tracking vector for every successful End-to-End handshake.
- `timestamp_slot`: (Integer) The slot at which the final Data or ACK frame successfully concluded the transaction.
- `protocol`: (String) The MAC Protocol generating the success event.
- `sender_id`: (Integer) The integer ID (0 to N-1) of the transmitting Drone.
- `receiver_id`: (Integer) The destination ID. Currently hardcoded to `-1` representing a shared general Sink/Base Station in a star topology.
- `packet_id`: (Integer) Incremental trace ID for debugging localized drone transmission sequences.
- `status`: (String) Outcome literal, e.g., "success".
- `retry_count`: (Integer) How many sequential MAC retries/collisions it took to finally deliver this specific packet (CSMA/CA specific).

### 2.4 `end_to_end_delay_vs_traffic_rate.csv`
Targeted isolation array extracting absolute delay metrics explicitly formatted for external plotting/importing.
- `traffic_rate`: (Integer) The aggregate offered load.
- `traffic_rate_unit`: (String) Hardcoded to "packets/sec".
- `end_to_end_delay`: (Float) The average absolute seconds the protocol took to deliver a generated packet.
- `delay_unit`: (String) Hardcoded to "seconds".
- `protocol`: (String) The specific MAC identifier.
- `N`: (Integer) Node count for this matrix row.
- `trial_id`: (String) The exact timestamped Trial ID generating this row data.

### 2.5 `comm_log.csv` (MARL / Fading Enabled)
High-resolution communication event log mapping per-link conditions during MARL execution or Fading tests.
- `timestamp_slot`: (Integer) The specific simulation slot the transmission occurred.
- `sender_id`: (Integer) The node ID transmitting the frame.
- `receiver_id`: (Integer) The intended destination node ID.
- `status`: (String) Outcome literal, e.g., "success" or "drop".
- `snr_db`: (Float) The calculated Signal-to-Noise Ratio (SNR) in decibels at the receiver, incorporating path loss and dynamic fading channel conditions.
- `ber`: (Float) The Bit Error Rate calculated instantaneously based on the `snr_db` and selected modulation scheme.
