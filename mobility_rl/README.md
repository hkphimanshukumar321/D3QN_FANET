This repository provides a rigorous, generic, and mathematically unbiased simulation environment for comparing multiple Medium Access Control (MAC) protocols, currently strictly validating **Slotted ALOHA**, **Round-robin TDMA**, and **CSMA/CA (802.11 DCF-style)**.

The framework explores throughput limits, channel utilization, and queuing dynamics under heavy scaling—specifically designed for Unmanned Aerial Vehicles (UAVs) / Flying Ad-Hoc Networks (FANETs).

## 2. Unbiased & Generic Algorithm Architecture
The framework operates with **strict algorithmic neutrality**. 

**Core Implementations:**
- **TDMA**: Enforces strict scheduling across assigned `$N$` slots.
  - *Guard Time*: Enabled via `TDMA_GUARD_TIME_S` in `config.py` (default: 1 µs). This mathematical gap space natively dilutes theoretical TDMA slot throughput to simulate real-world transmission propagation spacing and slightly increases delay bounds. 
- **CSMA/CA**: Executes standard DCF mechanics: Carrier Sensing, DIFS, SIFS, ACK timeouts, and Binary Exponential Backoff.
- **Slotted ALOHA**: Models uncoordinated stochastic transmissions with rigid timing overlaps.

**Consistency Guarantee:**
None of these mathematical implementations are "hard-fitted" to benefit under specific conditions outside their intrinsic mechanics. All three protocols are fed from the *exact same Poisson-arrival traffic generation logic*, managed by the *exact same queue limitation framework (QMAX)*, and processed by a *unified Logger/Observer struct* to guarantee precision tracking. As such, adding a new customized algorithm (e.g. an RL MAC) will compete entirely on its structural merits under fair grounds.

## 3. Explicit Simulation Architecture & Assumptions

### A. CSMA/CA Protocol Assumptions
- **Variant:** The framework implements standard **CSMA/CA 802.11 DCF-style**. It does *not* utilize RTS/CTS handshaking. 
- **Mechanisms:**
  - Standard DCF Interframe Space (**DIFS**) barrier before countdown.
  - Short Interframe Space (**SIFS**) prepending the Acknowledgment (**ACK**).
  - **Binary Exponential Backoff (BEB)** using parameterized `cw_min` and `cw_max`. 
  - Standard carrier-sensing physical freeze triggers. All counting nodes dynamically freeze during busy slots.

### B. Default Fading and Channel Models
- **Fading:** No geographical fading, path-loss, Rayleigh, or Nakagami models are enabled. It simulates an **Ideal Channel Condition**. 
- Packets are assumed perfectly delivered at PHY limits (`phy_rate_bps`) immediately, provided zero mathematical collision overlap occurs. 

### C. Substitute Metrics (Why BER is Unsupported)
- **Bit Error Rate (BER):** Because this framework is a **macroscopic MAC-level simulation** assuming an ideal propagation channel without bit-level decoding or RF noise injections, **BER is not supported and should not be used as a metric**.
- Instead, the simulation strictly validates performance via:
  1. **Packet Drops** (Buffer capacity overflow & MAC/ACK timeout active discardings)
  2. **End-to-End Delay** and **Average Queue Length**
  3. **Payload Throughput (Mbps)**
  4. **MAC-Collision Overlap Counts**
  5. **Channel Utilization Efficiency**

### C. Acknowledgment (ACK) Behavior
- **Delay Model:** Implicit successful ACKs take a fixed temporal overhead of `ack_slots` following an `sifs_slots` gap.
- **Collision & Timeout:** If two nodes transmit concurrently, both fail. The sender waits an exact `ack_timeout_slots` duration (representing the lack of returning acknowledgment). Upon timeout, the sender invokes BEB contention scaling and attempts retransmission.
- **Drop Threshold:** Retransmissions are strictly bounded by `max_retry` (default 7). Once exceeded, the MAC actively drops the payload entirely and resets the window `CWmin`.

### D. CSMA Degradation at High Load
Under intensive scaling profiles (e.g. $N \ge 1000$), CSMA mathematically degrades and plateaus well beneath theoretical TDMA limits (e.g., capping at ~68-75%). This occurs primarily due to:
1. **Collision Avalanche Matrix:** Massive node arrivals intrinsically force simultaneous backoffs down to exactly `0` concurrently, spiking the collision rate. This directly enforces massive `ACK_TIMEOUT` penalties globally continuously, vastly outweighting functional airtime.
2. **Backoff Overhead Dilution:** Even if random integers mitigate a collision, with `CWmax` approaching 1023, the raw sum of silent slots wasted waiting for countdowns across the network becomes a severe statistical tax robbing the channel of payload activity compared to rigid $O(1)$ TDMA slot scheduling.  

### E. Traffic Generation and Receiver Topology
- **Traffic Origin:** The simulation uses a continuous **Poisson generation process**. 
  - *Parameter:* The `offered_total_pps` (packets/sec) dictates the aggregate load. This is proportionally divided to find `lam_node` (λ per node).
  - *Method:* Packet inter-arrival times for each distinct node are sampled completely independently using memoryless exponential distributions (`numpy.random.exponential(1.0 / lam_node)`).
  - *Independence:* Senders do **not** generate data synchronously. The timing of packet availability is entirely asynchronous. **Bursty, correlated, or periodic ON/OFF traffic behaviors are currently unsupported.**
- **Receiver Topology:** The experimental model evaluates generic **Medium Access Contention** limits, not network-layer topology.
  - Senders lack explicit 1-to-1 recipient physical IDs; they simply contend for the physical RF medium. 
  - The model effectively acts as a **many-to-one abstract sink** or **perfect broadcast** physics environment. When a sender functionally secures the physical slot without RF overlap, the packet is instantly tallied as a successful generic delivery. This approach strictly isolates MAC-layer limitations from upper-layer routing/addressing complexities.

## 4. Interpreting Outputs and Graphs
When a simulation fully processes a traffic sweep, it generates $4$ primary graphical analyses stored in the `results/.../images/` boundary for that trial.

### A. Protocol Comparison: Throughput (`throughput_vs_load.png`)
- **What is Plotted:** 
  - *X-Axis*: Offered Traffic Rate (Total packets generated per second across all nodes)
  - *Y-Axis*: Target Throughput (Total successful Payload Mbps transiting the channel)
- **Compared MACs:** ALOHA, TDMA, CSMA/CA
- **Conclusion:** Showcases the functional capacity. For instance, CSMA/CA leads at low-loads (fast idle-resolutions), but during peak contention bounds, TDMA handles saturation perfectly while CSMA suffers a "capacity depression" due to massive collision/backoff computations. ALOHA predictably creates a short bell-curve collapse.

### B. Protocol Comparison: Channel Utilization (`utilization_vs_load.png`)
- **What is Plotted:** 
  - *X-Axis*: Offered Traffic Rate (pps)
  - *Y-Axis*: Channel Utilization (Percentage of time exactly `1` node owns the medium successfully, $0.0 - 1.0$)
- **Compared MACs:** ALOHA, TDMA, CSMA/CA
- **Conclusion:** Visually traces how much of the raw theoretical PHY pipe is actively shipping payloads. In dense configurations ($N=2000+$), this graph will plainly identify how much airtime is utterly wasted purely on overlapping carrier sensing resolutions (for CSMA) or constant blind impacts (ALOHA).

### C. Protocol Comparison: Queue Occupancy (`queues_vs_load.png`)
- **What is Plotted:** 
  - *X-Axis*: Offered Traffic Rate (pps)
  - *Y-Axis*: Average Queue Length (number of packets dwelling inside node buffers)
- **Compared MACs:** TDMA, CSMA/CA
- **Conclusion:** Illustrates the congestion point (latency onset). When the lines strictly plateau at `QMAX` (e.g. 20 packets), the network is beyond mathematical saving and heavily dropping metrics. 

### D. Protocol Comparison: Packet Drops (`drops_vs_load.png`)
- **What is Plotted:** 
  - *X-Axis*: Offered Traffic Rate (pps)
  - *Y-Axis*: Total pack counts discarded
- **Compared MACs:** ALOHA, TDMA, CSMA/CA
- **Conclusion:** Drops encompass both Queue overflow (Buffer drops) and MAC unresolvables (e.g., repeating a back-off retries $>MAX\_RETRY$ causing deliberate discarding). 

## 5. Time-Series Buffer Usage Logging (CSVs)
Alongside metric summaries, the latest iterations guarantee dedicated, time-resolved queuing analytics directly saved into:
- `results/.../csv/buffer_usage_CSMA_CA.csv` (and equivalents for ALOHA/TDMA).

**Recorded per interval loop (e.g., sweeping every 1000 simulation slots):**
- `slot`: The exact discrete time index.
- `max_capacity`: Network total limit (`N` * `QMAX`).
- `used_capacity`: Current aggregate buffer capacity in use.
- `unused_capacity`: Wasted/empty buffer space mathematically remaining.
- `enqueues`/`dequeues`/`drops`: Granular counters measuring exact state transition overheads since the last logging window.

## 6. Run Execution and Storage Mechanics
Running an experiment pipeline is vastly simplified via orchestration using `run_experiments.py`. 

### How to Run:
Use python to trigger the work orchestrator pointing directly to a configuration profile:
```bash
python work/run_experiments.py configs/high_load_N100.json
```

### Folder Generation Rules:
Rather than continuously deleting/truncating previous graphs, the script guarantees preservation.
When triggered, `run_experiments.py`:
1. Constructs a directory based on the specific variables in effect: `N[Size]_PHY[Rate]M_Q[Buffer]`/
2. Creates an execution isolation envelope using time: `trial_YYYYMMDD_HHMMSS`/
3. Dumps `config, seeds, git-commits` directly into `metadata.json` for validation.
4. If you run the exact same `high_load_N100.json` multiple times, it will simply mint a new `trial_` folder inside `N100_PHY10M_Q20`, ensuring zero overwriting. 

You can dynamically adjust $N$, `phy_rate_bps`, or array configurations by modifying the raw JSONs; the directory engine will handle the branching dynamically.

## 7. Core Formulas and CSV Metrics

The framework generates several highly detailed CSV logs (`summary_metrics.csv`, `buffer_usage_XXX.csv`, `ack_success_log.csv`, and `end_to_end_delay_vs_traffic_rate.csv`). All formulas actively correspond to the exact programmatic logic in `baseline.py`.

### Primary Mathematical Formulas

*   **Throughput (Mbps)**
    ```text
    Throughput = (Total Successful Packets * Payload Size in Bits) / Simulation Time in Seconds
    ```
    *(Note: This strictly excludes bits consumed by RTS/CTS/ACK headers and collided frames).*

*   **End-to-End Delay (Seconds)**
    ```text
    Per-Packet Delay = Time_Receive_Success - Time_Packet_Generated
    Average E2E Delay = Sum of all Per-Packet Delays / Total Successful Packets
    ```
    *(Note: Calculates based on exact mathematical slot indices converted to seconds).*

*   **Average Queue Occupancy (Packets)**
    ```text
    Average Q_Len = Total instantaneous queue lengths logged across all slots / (Total Slots * N)
    ```

*   **Channel Utilization Ratio**
    ```text
    Utilization = Total Channel Busy Slots / Total Simulation Slots
    ```

*   **Total Dropped Packets**
    ```text
    Drops = Packets_Dropped_Queue_Full + Packets_Dropped_MAC_Retries_Exhausted
    ```

## 8. 3D Mobility Extension (Many-to-One, Variable Speed)

### Overview
The framework includes a 3D UAV mobility subsystem implementing bounded movement within a cube `[0,A]×[0,B]×[0,C]`. All N UAVs communicate to a single fixed sink/base station (many-to-one topology). Mobility runs as an independent simulation layer producing additive CSV/plot outputs.

### Mobility Models (`MOBILITY_MODEL` in `config.py`)
| Model | Config Value | Description |
|---|---|---|
| Gauss–Markov | `"gauss_markov"` | Correlated velocity; tunable via `GM_ALPHA` (0=random, 1=deterministic) |
| Random Waypoint | `"random_waypoint"` | Fly to random point, pause `RWP_PAUSE_TIME` seconds, repeat |
| Random Walk | `"random_walk"` | Random direction changes per speed update interval |
| Circular/Spiral | `"circular"` | Circular orbit with variable ω and optional vertical climb/descent |

All models enforce boundary reflection/clamping to keep positions inside the cube.

### Variable Speed (`SPEED_MODE`)
| Mode | Description |
|---|---|
| `"uniform"` | Speed ∈ Uniform(V_MIN, V_MAX), re-sampled every `SPEED_UPDATE_INTERVAL` |
| `"gaussian"` | Speed ∈ N(V_MEAN, V_STD), clamped to [V_MIN, V_MAX] |
| `"per_node_uniform"` | Each node has a random base bias with jitter |
| `"piecewise"` | Alternates cruise/hover/sprint phases |

### Sink Model
Fixed position at `(SINK_X, SINK_Y, SINK_Z)` inside the cube. Optionally made mobile in future phases.

### Link Model
- **Phase-1 (default):** Range-gated binary link — `link_up = 1 if d ≤ COMM_RANGE_R else 0`
- **Phase-2 (optional):** Path-loss success probability `P_succ(d) = exp(-k·d^η)`, enabled via `ENABLE_PATHLOSS`
- **Optional:** Propagation delay `τ = d/c`, enabled via `ENABLE_PROP_DELAY`

### New Outputs (Per Run)
| File | Description |
|---|---|
| `csv/mobility_positions.csv` | Columns: `timestamp, uav_id, x, y, z, vx, vy, vz, speed` |
| `csv/uav_sink_distance.csv` | Columns: `timestamp, uav_id, d_to_sink, link_up` |
| `images/uav_trajectories_3d.png` | 3D trajectory plot for top-K UAVs |
| `images/distance_to_sink_vs_time_uavK.png` | Distance time series with comm range line |
| `images/link_up_ratio_vs_time.png` | Fraction of connected UAVs over time |
